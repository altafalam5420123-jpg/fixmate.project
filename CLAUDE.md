# CLAUDE.md - FixMate Project Guidelines

## Project Overview
FixMate is a dual-sided on-demand home services platform (Customer & Worker) built for Tier-2/3 Indian cities.
It enables OTP-based auth, instant service booking, safety start codes, quoting, in-app wallet, Razorpay payments, and Android mobile wrapping via Capacitor.

---

## Tech Stack & Key Versions
- **Runtime & Backend:** Node.js (>=20), Express 4.21.2
- **Database:** SQLite via `better-sqlite3` (^12.2.0) with WAL mode & automated pragmas
- **Security & Auth:** `jsonwebtoken` (^9.0.2), `otplib` (^13.5.0), crypto HMAC-SHA256
- **Frontend Client:** Vanilla JavaScript (ES2022+), CSS3 (CSS custom properties, dark mode), SVG vector assets
- **Mobile Engine:** Capacitor Core & Android (^8.5.2) with Gradle build system

---

## Commands

### Server (`fixmate/server`)
- **Install dependencies:** `npm install`
- **Development (hot-reload):** `npm run dev` (Node `--watch src/server.js`)
- **Start production:** `npm start`
- **Run tests:** `npm test`

### Mobile & Build (`fixmate/`)
- **Generate API Config:** `npm run api:config`
- **Generate Icons:** `npm run icons:generate`
- **Sync Capacitor to Android:** `npm run android:sync`
- **Open Android Studio:** `npm run android:open`

## Detected Code Conventions
- **No Heavy Client Frameworks:** Keep frontend fast and vanilla; use declarative templates inside `app.js`.
- **State Machine Integrity:** Bookings transition strictly:
  `requested` → `assigned` → `on_the_way` → `inspecting` → `quoted` → `in_progress` → `completed` → `paid` (or `quoted` → `closed` if customer rejects quote).
- **Constant-Time Verification:** Always use `crypto.timingSafeEqual` for OTP hashes and payment signatures.
- **Double-Entry Ledger:** Any balance update in `users.wallet` MUST be wrapped in a database transaction with a corresponding row in `wallet_tx`.
- **Worker Commission Split:** Standard formula is 85% to worker wallet, 15% platform retention; customer receives 5% cashback on completed orders.

---

## Hard Rules & Non-Negotiables
1. **Never alter the SQLite database schema directly** without adding a structured migration block in `db.js` (`migrateSchema`) incrementing `user_version`.
2. **Never expose or commit secrets:** Razorpay key secrets, JWT secrets, Twilio credentials, or database files must remain in `.env` (gitignored).
3. **Never bypass OTP rate-limiting or HMAC verification:** Both IP rate limits (`express-rate-limit`) and per-phone hourly limits (`otp_rate_limits`) must be preserved.
4. **Never allow `localhost` for native Android builds:** Capacitor Android requires a public HTTPS origin configured in `API_BASE_URL`.
5. **Never delete existing features or break Hindi UI copy** without explicit user approval.

## Week 1 Gotchas for New Engineers
- **Gotcha 1 (Local OTP 503):** Without Twilio credentials, `DEV_SHOW_OTP=1` and `ALLOW_DEMO_TOPUP=1` MUST be explicitly set in `server/.env`. Otherwise `/api/auth/otp/send` throws a 503 error.
- **Gotcha 2 (Database creation):** `fixmate.sqlite` is generated in `server/` on the first run. Foreign keys are enforced (`foreign_keys = ON`).
- **Gotcha 3 (Customer Start Code):** Workers cannot start a job (`/start`) without the customer providing their 4-digit `start_code`. There is a 5-try brute-force lock.
- **Gotcha 4 (Razorpay Capture Check):** Payment verification requires both signature match AND a server-to-server check confirming payment status is `captured`.
